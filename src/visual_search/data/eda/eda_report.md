## 2. Image-сторона

### 2.1. Битые / нечитаемые

Поле `validation_status` уже проставлено серверным валидатором при загрузке. Из 1,214,677 строк:

- `ok`: **1,214,314** (99.97%)
- любые другие значения (read-error, decode-error, format-mismatch): **363** (0.03%)

→ Фильтр Phase 1.1 убирает эти 363 строки.

### 2.2. Размер изображения

Все картинки приведены к стандарту 480px по высоте (`max_h=480` ровно). Ширина варьируется в зависимости от исходного aspect ratio.

| Метрика | width | height |
|---|---:|---:|
| min | 29 | 54 |
| max | 640 | 480 |
| mean | 375.7 | 478.3 |
| median | 360 | 480 |

**Топ-1 размер:** `360×480` (548,852 картинки, **45.2%**) — стандартный размер карточки.

**Распределение очень маленьких картинок** (min(w,h) < N):

| Порог | Картинок | % от ok |
|---|---:|---:|
| < 200 px | 3,464 | 0.285% |
| < 150 px | 527 | 0.043% |
| < 100 px | 64 | 0.005% |
| < 50 px | 3 | 0.000% |

**Наблюдение:** все картинки с `min(w,h)<100` (64 шт.) — это коллажи-полоски (например, 29×480, 84×480, 640×95). Они **уже отсеиваются** Phase 2 через `pixel_thin` (aspect<0.3 или >3.0). Отдельный min-size cutoff **не нужен**.

### 2.3. Aspect ratio

- p5 = 0.46
- p50 = 0.75 (доминирует портрет 360×480)
- p95 = 1.33
- p99 = 1.77
- хвосты: aspect<0.3 → коллажи-полоски; aspect>3.0 → горизонтальные баннеры

→ Phase 2 фильтрует `aspect∉[0.3, 3.0]` → **553 drops**.

### 2.4. Пустые / однотонные

Используем энтропию grayscale-канала и edge_density (средняя норма градиента).

На 50k сэмпле:
- entropy: min=1.22, **median=7.23**, p1=3.67
- edge_density: median=8.93, p1=2.96

Распределение тяжёлое в сторону содержательных картинок. «Пустыми» классифицируем `entropy<1.5 AND edge_density<1.0` — заведомо однотонные плэйсхолдеры (черные/белые квадраты).

→ Phase 2 → **16 drops** на 1.05M. False positives на 50k не обнаружены при визуальном осмотре.

**Почему такие консервативные пороги:** при entropy>1.5 уже встречаются валидные светлые платья на белом фоне. См. подробности в [`filtering_report.md`](filtering_report.md#21-pixel_blank--16-строк).

## 5. Дубликаты

### 5.1. SHA256 (байт-идентичные)

- Помечено в манифесте как `sha256_duplicate=True`: **207,315 строк** (17.1%)

⚠️ **НЕ** дропаем напрямую — это привело бы к потере **35,659 items (13%) целиком**. Используем умную замену через cross-item phash dedup (см. ниже).

### 5.2. Phash (perceptual hash)

- Уникальных phash: 1,043,857
- Phash, который встречается > 1 раза: 224,775 строк (18.5% — больше чем sha256-дубли, потому что phash ловит и визуально-похожие, не только байт-идентичные)
- **Cross-item phash групп**: 49,314 (один phash → несколько разных items) — оставляем 1 канонического представителя, остальное в drop.

**Топ-2 phash-группы:**

| Phash | Кол-во копий | Что это |
|---|---:|---|
| `d86d27d23865c71a` | 7,149 | Серый баннер «МЫ: Продаём товары ведущих мировых брендов» — рекламная плашка |
| `ed3e92c396306595` | 7,149 | Серый баннер «Повреждена упаковка? Перепутали заказ?» — служебная плашка |

Эти две группы вдвоём составляют 14,296 удалений (**8.7% всех Phase 1 drops**).

Полный анализ в [`filtering_report.md`](filtering_report.md#12-cross-item-phash-deduplication--163421-строка).

## Воспроизводимость

```bash
# 1) EDA (Phase A: статистики манифеста; Phase B: pixel-stats на 50k сэмпле)
python3 eda.py --base data --sample 50000 --workers 4 --out-dir out

# 2) Полный pixel-stats для финальной фильтрации (после распаковки upload.tar.gz)
python3 run_pixel_stats_full.py \
  --kept-csv out/relevant_phase1.csv \
  --images-root data/full/dataset_1M/images \
  --workers 12 --out-csv out/pixel_stats_full.csv

# 3) Двухфазный фильтр → relevant_final.csv
python3 apply_filter.py \
  --manifest data/tmp_manifest_validated.csv \
  --pixel-stats out/pixel_stats_full.csv \
  --out-dir out/full
```
