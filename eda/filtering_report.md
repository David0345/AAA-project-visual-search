## Что мы фильтровали и почему

### Phase 1 (только манифест, без чтения пикселей)

#### 1.1. `validation_status_not_ok` — **−363 строки**

Тривиальный фильтр: в манифесте уже есть поле `validation_status`, проставленное на серверном валидаторе. Берём только `'ok'`. Эти 363 строки — повреждённые JPEG, неоткрываемые файлы, и т.п.

#### 1.2. Cross-item phash deduplication — **−163,421 строка**

Это центральная идея фильтра. Phash (perceptual hash) одинаков у двух картинок, если они **визуально неотличимы**. Сырая статистика по полному манифесту:

- Уникальных phash: 1,043,857
- Phash, который встречается > 1 раза: 224,775 строк (18.5%)

Но **не каждое совпадение phash означает мусор**. Различаем два сценария:

| Кейс | Что это | Действие |
|---|---|---|
| **Within-item:** один phash появляется у нескольких картинок **одного товара** | Разные углы / освещение одной и той же позиции (часто бывает, если продавец делает первое и второе фото с очень похожим ракурсом) | **Оставляем все** — это валидные альтернативные виды |
| **Cross-item:** один phash появляется у картинок **разных товаров** | Сток-фото, скриншоты, рекламные баннеры, картинки операторов/служб поддержки | **Оставляем только 1 каноничный экземпляр на phash** |

Имплементация в [apply_filter.py:65-66](apply_filter.py#L65-L66):
```python
cross_item_phashes = {ph for ph, items in phash_items.items() if len(items) > 1}
```

Итог: **49,314 cross-item phash-групп**, в которых лежали 212,735 строк → оставили по 1 представителю на группу = 49,314 строк, выкинули **163,421**.

**Выбор канонического представителя** (`is_title=True` приоритетней → меньший `item_id` → меньший `image_id`): берём ту строку, которая «больше похожа на оригинал» — title-картинка с самого раннего объявления вероятнее всего и есть первоисточник, а не копия.

##### Топ-2 phash-группы, отсеянные через cross-item dedup

### Phase 2 (требует пикселей)

#### 2.1. `pixel_blank` — **−16 строк**

Картинка отсеивается, если **энтропия < 1.5 бит** (по grayscale) **И** edge density < 1.0 (средняя норма градиента).

- Энтропия 0 = идеально однотонная картинка (один цвет, чистый чёрный/белый).
- Энтропия < 1.5 ≈ почти однотонное изображение с 2-3 микроградациями.

Пример: `images/812/758/44546812758.jpg` — `pixel_blank(ent=0.75, ed=0.62)` — чёрный квадрат с почти невидимым «Avito» в углу. Скорее всего, продавец загрузил картинку до того, как сделал реальное фото.

**Почему такие консервативные пороги?** Распределение энтропии на 50k-сэмпле: медиана = 7.23, p1 = 3.67. Визуальный осмотр на 50k показал:
- entropy < 1.5 — реальные плэйсхолдеры, без ложных срабатываний.
- entropy 1.5–3.0 — встречаются валидные картинки в светлых тонах (бежевые платья на белом фоне).
- entropy 3.0–4.0 — практически весь массив реальных фото.

Поэтому остановились на `1.5 AND edge<1.0` — крайне консервативный фильтр, который удаляет только заведомо пустые картинки. False positives на 50k сэмпле не обнаружены.

#### 2.2. `pixel_thin` — **−553 строки**

Aspect ratio (width / height) < 0.3 ИЛИ > 3.0 — это **узкие полоски-коллажи**, которые плохо работают как поисковые эмбеддинги (модели, обученные на стандартных аспектах ~0.75, искажают коллажи).

Распределение aspect на 50k:
- p5 = 0.46, p50 = 0.75 (доминирует 360×480), p99 = 1.77.
- За пределами [0.3, 3.0] — действительно очень редкие крайние случаи (длинные платья в одном вертикальном кадре или горизонтальные баннеры).

Пример: `images/649/153/25165649153.jpg` — `aspect=0.29` — кадр длинного зелёного платья по всей высоте, очень узкий — для image-similarity сложен.

**Альтернатива, которую отвергли:** более жёсткие пределы `[0.5, 2.0]` — отбросили бы ~5–8% валидных длинных платьев.

## Воспроизводимость

```bash
# 1) Phase 1 + Phase 2
python3 apply_filter.py \
  --manifest data/tmp_manifest_validated.csv \
  --pixel-stats out/pixel_stats_full.csv \
  --out-dir out/full

# 2) если pixel_stats_full.csv нужно перегенерировать (12 воркеров, ~3 мин):
python3 run_pixel_stats_full.py \
  --kept-csv out/relevant_phase1.csv \
  --images-root data/full/dataset_1M/images \
  --workers 12 \
  --out-csv out/pixel_stats_full.csv
```

Артефакты:
- `out/full/relevant_final.csv` — **1,050,324 строки**, финальный список релевантных
- `out/full/relevant_phase1.csv` — после Phase 1 (для отладки)
- `out/full/dropped_phase1.csv` — со столбцом `drop_reason` (validation/cross-item)
- `out/full/dropped_phase2.csv` — со столбцом `drop_reason_p2` (blank/thin)
- `out/full/filter_summary.json` — числовая сводка
- `out/pixel_stats_full.csv` — pixel-level stats для всех 1.05M kept-картинок (entropy, edge_density, aspect и др.)
- `report.html` - аналитика в удобном формате с примерами
