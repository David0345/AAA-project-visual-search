# Построение тренировочного датасета (train.parquet)

Скрипт `prepare_train_data.py` создаёт тренировочный датасет для задачи поиска по тексту и изображению.  
Датасет формируется из объявлений Avito (женская одежда), прошедших EDA и фильтрацию.

## Что делает скрипт

1. Загружает `items.csv` и `images.csv` из указанной папки.
2. Отфильтровывает невалидные изображения по списку `valid_image_ids.csv` (результат EDA‑фильтрации).
3. Определяет титульное изображение (`is_title=True`) и собирает остальные изображения товара в список.
4. Формирует `product_text` – краткое текстовое описание товара, состоящее из предмета одежды, цвета, бренда и состояния через запятую.
5. Генерирует `queries` – разнообразные короткие поисковые запросы (1–6 слов), которые пользователь мог бы ввести в строку поиска.

## Логика генерации запросов

### Используемые атрибуты
- **predmet_odezhdy** (предмет одежды, например «Платья»)
- **cvet** (цвет, например «Чёрный»)
- **brand** (бренд, например «Stradivarius»)

Поля `param2` (дублирует `predmet_odezhdy`) и `sostoyanie` (состояние) **не используются** в запросах.

### Словари синонимов

Чтобы покрыть реальные формулировки пользователей, для каждой категории одежды составлен список естественных синонимов в файле `category_synonyms.py`. 

*Пример: для категории «Пиджаки и костюмы» запросы будут содержать слова «пиджак», «жакет», «костюм» и т.д., а не полное название категории.*

### Транслитерация брендов

Иностранные бренды часто ищут на русском (например, «адидас» вместо «Adidas»).  
Для самых популярных брендов (топ-100) составлен словарь `brand_translit.py` с русскими соответствиями. При генерации запросов используются оба варианта.

### Очистка бренда

Перед поиском в словаре название бренда очищается от специальных символов (®, & и т.п.) и приводится к нижнему регистру.  
Бренды «Другой» и «Без бренда» отбрасываются, так как не несут полезного сигнала.

### Что не включается в запросы

- **Категория «Другое»** – слишком разнородная, текстовые запросы для неё не генерируются (изображения остаются для поиска по картинке).
- **Состояние** – пользователи редко ищут «в хорошем состоянии», а грамматически верное согласование с родом предмета усложнило бы код. Отказ от состояния упрощает датасет и не снижает качество.
- **Визуальные теги (котики, цветочки)** – на этапе бейзлайна сознательно не используются. При необходимости добавим на следующей итерации.

### Разнообразие формулировок

Для каждого товара генерируются все комбинации предмета, цвета и бренда с разным порядком слов (например, «чёрный пиджак» и «пиджак чёрный»). Это помогает модели стать устойчивой к перестановкам и частичному совпадению слов.

## Почему не были использованы другие подходы

- **Связные тексты (image captioning / LLM)** – требуют дополнительных моделей, увеличивают время генерации и могут внести шум (стоп-слова, оценочные прилагательные). Простой конкатенационный способ даёт контролируемый и чистый сигнал.
- **Генерация визуальных тегов с помощью CLIP-like модели** – на старте отложена, чтобы сфокусироваться на надежном бейзлайне.

## Структура выходного файла

`train.parquet` содержит следующие колонки:

| Колонка              | Описание |
|----------------------|----------|
| `item_id`            | ID товара |
| `title_image_path`   | Путь к титульному изображению |
| `other_image_paths`  | Список путей к остальным изображениям товара |
| `product_text`       | Структурированное описание товара |
| `queries`            | Список поисковых запросов |
| `predmet_odezhdy`    | Исходная категория |
| `param2`             | Подкатегория (заполнена, но не используется) |
| `cvet`               | Цвет |
| `brand`              | Бренд |
| `sostoyanie`         | Состояние |
| `category_name`      | Название верхнеуровневой категории |

## Запуск

```bash
python prepare_train_data.py \
    --data-dir путь/к/dataset_20250601_20250606_1M_v1 \
    --valid-ids valid_image_ids.csv \
    --output train.parquet
